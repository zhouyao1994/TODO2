# Internationalization (i18n)

Detail reference for `src/i18n/` (the UI language and message catalogs). Load when adding UI copy or a language.

## What it is

The app speaks English and Simplified Chinese. Only **UI copy** is translated: task titles, notes, list / person / status / tag names and other stored data stay exactly as the user wrote them. A few stored defaults (a new list's name, the default layout's name) are data too and are not re-translated later.

| Abstraction | Location | Purpose |
|-------------|----------|---------|
| Language model | `src/models/language.ts` | `Language` (`en`, `zh-CN`), `LanguagePreference` (`system` + the two languages), `languageForPreference` (a `zh-*` browser reads as Simplified Chinese, anything else as English) |
| Lookup | `src/i18n/index.ts` | `t(key, params)`, `translateText(english)`, `locale()`, `getLanguage`, `setLanguagePreference`; sets `<html lang>` and mirrors the choice to `localStorage` (`todo2.language`) for the first synchronous read before IndexedDB opens |
| Catalogs | `src/i18n/messages/en.ts`, `zh-CN.ts` | Flat `key → copy` maps. `zh-CN` is typed `Record<MessageKey, string>`, so `tsc` fails on a missing or unknown translation |
| Setting | `stores/settings-store` (`language`, `setLanguage`), `data/setting-keys` (`language`), `data/import-validation` | `system` is the default and stored as no row; a pinned language is a row. Settings › Appearance › Language is the only control |

## Using it

- **Components and services** call `t('ui.save')` and pass parameters: `t('ui.in_widgets', { n: 3 })` → `Shared · 3 widgets` / `共享 · 3 个组件`. Unknown `{name}` placeholders are left alone.
- **Labels defined as plain data** (widget kinds, filter field names, settings section labels, option labels) stay English in the data and are wrapped where they render: `translateText(widgetKindLabel(kind))`. `translateText` looks the English text up in the catalog and returns anything that is not a catalog value (user text) unchanged.
- **Dates and times** go through `locale()` (`formatDateWith` already does), so the same code formats `Oct 5` in English and `10月5日` in Chinese.
- **Plurals** are explicit, as before: pick a `_one` / `_many` key at the call site (`n === 1 ? t('ui.day_count_one') : t('ui.day_count_many', { n })`).

## Adding a message

1. Add the key to `en.ts` with its English copy.
2. Add the same key to `zh-CN.ts` (the type checker fails until you do).
3. Use it at the call site (or `translateText` when the copy is defined in plain data).

Keys are stable ids (`ui.new_task`), not English text: changing the English copy does not break a translation. Do not translate user data or compose a sentence out of translated fragments where Chinese word order would break — make one message with `{parameters}` instead.

## Changing the language

The setting is saved (`settings-store.setLanguage`), applied immediately (`<html lang>`, catalog lookup) and the Settings control reloads the page. The reload is deliberate: module-level labels and `React.memo` rows keep their first render, so reloading is what makes every string — not only the currently mounted components — switch language.

## Tests

`src/test/i18n/i18n.test.ts` checks the model, catalog parity, interpolation and `translateText`; `src/test/stores/language-setting.test.ts` checks the stored preference and startup application. Tests run in English (`system` → the JSDOM browser), so existing English text assertions stay valid; set the language inside a test and restore it afterwards (the module keeps it for the worker).
