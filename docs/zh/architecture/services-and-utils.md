# 服务、Hooks 与工具函数

> 本文件是对英文原文的中文翻译，仅供参考；如有出入，以英文原文为准。

`src/services/`（非 UI 逻辑）、`src/hooks/`（自定义 React hooks）与 `src/utils/`（纯工具函数）的详细参考。当涉及 NLP、重复任务、文件存储、列表解读、拖放逻辑、键盘快捷键或日期辅助函数时加载本篇。

| Section, ListSectionsSpec, ListSectionsContext, buildListSections, listSortComparator, isUngroupedSectionKey | services/list-sections.ts | 列表小部件唯一的分区（section）构建器（`buildList` → `useBuiltList` → `ListWidget`），因此同一个列表定义在每个小部件中都产出相同的分区。`buildListSections(members, {groupBy, sortBy, sortDirection?, restrictToPersonIds?, restrictToTagIds?}, ctx)` 先用 `listSortComparator(sortBy, { direction: sortDirection, … })` 排序（因此每个分区产出时都已有序；分组保持输入顺序），再通过 `utils/task-grouping.partitionByGroup` 划分。分区：截止日期 / 跟进 → Overdue（逾期，`--color-overdue`）/ Today（今天，`--color-accent`）/ This Week（本周，`--color-text-secondary`）/ Later（稍后，`--color-text-muted`），然后是 "No Due Date"（无截止日期）/ "No Follow-up"（无跟进）（键 `none`；每个尾部的 "No …" / Unassigned 分区均用 `--color-text-muted`）；成员（people）→ 成员名，强调色取 `person.color`（未设置时为 undefined），按字母序，然后是 "Unassigned"（未分配）；状态（status）→ 注册表 `sortOrder`、状态颜色，然后是 "No Status"（无状态）；标签（tag）→ `#name`、标签颜色、按字母序，然后是 "No Tag"（无标签）；优先级（priority）→ Hot（热门，`HOT_COLOR`，火焰图标）、Focus（专注）、Urgent（紧急）、Important（重要）（各自为 `MARKER_COLOR`），然后是 "No priority"（无优先级，键 `no-priority`）—— Hot 按 `ctx.hotRule`（缺省即默认规则；仅未完成任务），Urgent 按 `ctx.urgentRange` 取生效的紧急（缺省 = 仅旗标）；`none` → 单个 `all` 分区（为空时则没有）。本构建不认识的已存储分组按 `none` 读取。限定（restrict）模式（生效筛选中的成员 / 标签勾选）：只显示这些分区，按勾选顺序；除非成员勾选中包含 `0`（Unassigned），否则尾部哨兵分区被丢弃。带有多个成员 / 标签 / 优先级分组的任务会出现在其中每一个里；空分组不显示。`listSortComparator(sortBy, { manualRanks?, today?, urgentRange?, direction? | replaceData, withDataReplaceHold, onDataReplaced, restoreFromImport, restoreBackup, cleanupCurrentAudit, DataReplaceSource, ReplaceBackup, ReplaceOutcome, ImportOutcome, RestoreOutcome, CleanupOutcome | services/replace-data.ts | store 之上**数据被替换的唯一途径** ——Settings › Import JSON（`restoreFromImport`）、Settings › Backups 的 Restore（`restoreBackup`：先于快照读取并检查备份，因为快照的清理可能删掉它；之后重新加载备份列表）、审计的清理（`cleanupCurrentAudit`：展示时报表，清理后清除，取消时保留）、同步文件的加载（`file-storage.applyFileData`）、追加导入（`append-import.runAppendImport`）。`replaceData(source, { backup, write })` 依次执行：笔记 store 的保持（hold）（`holdForDataReplace` ——先保存已输入的文本，使备份包含它；此后不再有保存落地）、备份（`{ operation }` = `takeSafetySnapshot`，取消 → `cancelled`，什么都不改；`best-effort` = 失败只记日志的快照，用于不损失任何内容的加载）、`write`、重新加载（`refreshAllStores`，清空撤销栈并清理被替换数据可能弄错的东西；追加导入后用 `refreshTaskStores`，它不替换任何内容），然后依次执行 `onDataReplaced(source)` 监听器（`sync-file` 加载后是 App 的清理检查）——某个重新加载或监听器失败不会阻止下一个，第一个失败在最后重新抛出 → `{ status: 'done', result, noBackup }`。`withDataReplaceHold(fn)` ——仅保持（hold）本身，用于同步文件的加载决策（hold 可嵌套） |

| fileStorageService | services/file-storage.ts | File System Access API 同步（文件 ↔ IndexedDB）。**在任何东西改变之前先由用户决定：** **启动**（`initialize()`，并发调用方共享）：已授权的句柄立即加载；需要授权的句柄标记 `needsPermission` 并弹出启动问题（`onLaunchPermission`）——`initialize` 只在该问题被回答后才 resolve（从问题的 Grant 进入 `reconnect({ onGranted })`：浏览器一答应 `onGranted` 就触发，先于加载；Continue 则在授权仍缺失的情况下 resolve）。一次加载（启动 / Grant Access / attach / `retry()`）会读取并用 `prepareImport` 处理文件且不动任何一侧，然后：任何失败（过大、读取错误、无效 JSON/行、过新、低于下限或无版本号——`too-old`、升级失败）→ **暂停**（`status.paused = {reason, message}`，不恢复数据、绝不写入；若 `getFile()` 再找两次——0.4 秒、再 0.8 秒后——仍找不到文件（云文件夹可能正在把新副本重命名到位），则忘记该句柄）。读取经由私有的 `readFileText`（读取前有 50 MB 上限；一次保存中途替换掉的 `File` 快照——`text()` 抛出的 `NotFoundError` / `NotReadableError`——会重新读取，至多 3 次，之后报 `read-error`），且先等待 `whenIdle()`；低于下限的文件绝不会被读入应用，也不会被一次加载写入（暂停为 `too-old`，消息中指明可转换它的更旧构建；只有存储胶囊里明确的 Keep browser data… 会覆盖它，且先备份其文本）；未同步的浏览器更改（`dirtySince`）发生在本浏览器上次同步的那个文件之上（`fileSavedAt` = 文件内容的身份标识——在保存防抖窗口内关闭的标签页、需要授权期间或同步暂停期间的编辑）→ 浏览器单纯领先：其数据不经询问直接写入文件（先备份文件文本，标记为 `'browser'`；更旧的文件先询问 `onConfirmFileUpgrade`，取消 → 暂停）；未同步的浏览器更改发生在其后已变更的文件之上，或浏览器有任务却没有同步记录 → `onConflict` → `'file'`（通过 `takeSafetySnapshot` 备份浏览器数据 → 恢复文件；备份失败会询问，取消则以 `backup-failed` 暂停）/ `'browser'`（文件文本 → `backupScheduler.snapshotFileBeforeOverwrite` → 覆盖）/ `'cancel'`（暂停）——当 `browserMatchesFile` 判定两侧已持有完全相同的数据时跳过（更旧的文件在其升级之后再比较，因此来自没有同步记录的构建、并在打开时被升级的浏览器，会与它同步中的文件匹配，转而得到升级询问）；干净的浏览器同步的是文件的更早版本 → 加载该文件（多机场景）；更旧但仍受支持的文件 → 先 `onConfirmFileUpgrade`（取消 → 暂停），然后恢复 + 重盖时间戳（restamp）。**事件：** `onStatusChange` 添加订阅者并返回其退订函数——每个订阅者收到每一次变更（抛异常的订阅者会被记入日志）。替换浏览器数据的加载就是一次数据替换（`replace-data.replaceData('sync-file', …)`）：各 store 在那里重新加载，`onDataReplaced` 监听器在那里得知。这些问题（`onConflict` / `onConfirmFileUpgrade` / `onLaunchPermission`）只有一个应答者：后注册的处理器替换先前的，且每个返回的移除函数在被替换后变成空操作。缺失处理器时按安全答案 resolve（保持暂停）。只要文件已附加，变更跟踪的 Dexie hook 就保持安装（暂停 / 需要授权期间同样如此）并把浏览器标记为 dirty；写入只在 `syncEnabled` 时发生；打开同步（`startSync`，每次加载 / 强制写入之后）会保存在其关闭期间记录的任何更改（例如某个 store 在重新加载时预置了一行），因此不会留下未同步的内容让下一次启动来询问。`overwriteFileWithBrowser()`（存储胶囊的 "Keep browser data…"，在 `too-new` / `too-old` 暂停时也会提供）先备份文件文本，然后覆盖并恢复同步（超过 50 MB 的文件不读取：`backup-failed`，文件原样不动）。**写入绝不重叠**（`saveInFlight`）：在一次写入期间请求的防抖保存会在其后重新排程；强制写入（创建 / 覆盖 / 升级 / 空文件预置）等待当前写入完成后再写——绝不丢弃；一次保存只写它启动时所用的句柄，且仅当该文件仍处于附加状态时才设置同步记录。`whenIdle()` 在没有写入在运行或已排程时 resolve（加载路径与 e2e 的 `readSyncFile` fixture 都等待它）。失败会记录日志（`console.warn`）并呈现在 `status.error` / 暂停消息中——但来自 `getFile()` / `text()` / `createWritable()` / 一次写入的 `NotAllowedError` 例外（浏览器在会话中途收回授权，或在加载时拒绝读取）：那会设置 `needsPermission`（同步关闭、保留句柄，存储胶囊显示 Permission needed → Grant access → `reconnect`，其加载会把期间所做的编辑写入未变更的文件），绝不会是 `Failed to save to file` 或暂停。**每一次写入既有文件内容**（已确认的升级、任一重写文件的冲突选择、浏览器单纯领先于未变更文件、保留浏览器数据的覆盖）都先备份原始文件文本（私有 `backupFileText` → `backupScheduler.snapshotFileBeforeOverwrite`）；备份失败或文件不可读则以 `backup-failed` 暂停且什么都不写——任何新的写入路径都必须照做。已确认的升级在重写文件失败时以 `write-failed` 暂停（浏览器持有升级后的数据，文件还是旧的；Retry 会再次询问）。被 `prepareImport` 修剪过的当前版本文件（它返回了警告——有部分被丢弃）也会在加载前备份其原始文本，因为第一次同步写入会在不含这些部分的情况下重写文件。加载遵循后来者优先：每次加载都递增一个代数（generation），仍在等待问题的更旧加载（store 会替它回答为已取消）会在下一个 await 处停止，不暂停也不写入；`disconnect` / `reset` 同样会让运行中的加载失效。每次写入都像导出一样被检查：超过 50 MB 的加载上限（每次写入都查），或未通过导入自检（`selfCheckExportJson` ——强制写入必查，否则至多每分钟一次）→ 仍然写入，且状态错误显示 `Saved, but the sync file would not load back: …`，直到出现一次干净的写入。`openFile`/`createFile`/`disconnect` 重置同步记录；`openFile` / `createFile` 在切换之前先存下所选句柄（`saveFileHandle`）——当浏览器做不到时，什么都不切换（先前附加的文件保留并继续同步），状态错误会说明这一点。`createFile` 建议 `todo2-data-YYYY-MM-DD.json`（`newSyncFileName`，本地日期）：浏览器会在 `showSaveFilePicker` resolve 之前清空在保存对话框中选中的既有文件，因此其文本无法备份——带日期的默认名让该建议避开更旧的同步文件，Settings › File storage 也说明了这一点。`isConnected` = 正在活跃同步。每一次替换浏览器数据的加载都经过 `takeSafetySnapshot`（浏览器备份失败会询问 "Continue without a backup?"；取消则以 `backup-failed` 暂停，什么都不改）——例外是浏览器已恰好持有该文件的数据时（完全相同——在该文件的升级（如有）之后——或干净且与该文件版本同步过），此时备份失败只记日志，因为这次加载不损失任何内容。加载决策在 `replace-data.withDataReplaceHold` 内进行（笔记 store 的
