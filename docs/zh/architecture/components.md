## 视图

| 抽象 | 位置 | 用途 |
|-------------|----------|---------|
| ROUTE_WORKSPACE, ROUTE_SETTINGS, LEGACY_ROUTES, AppRoute, SettingsRouteState | routes.ts | hash 路由器的路由路径。`App.tsx` 在 `/` 处渲染 `WorkspacePage`（`ROUTE_WORKSPACE`，位于作用域为 "Workspace" 的 `ErrorBoundary` 内）；`/settings` 在手机上渲染移动版 `SettingsPage`，在桌面上则打开 Settings 弹窗并重定向到 `/`（一个深链接）；`LEGACY_ROUTES` 中的每个旧页面路由（`/workspace`、`/list`、`/calendar`、`/dashboard`）以及任何未知路径都会（`<Navigate replace>`）重定向到 `/`。由 `App.tsx`、`BottomTabBar` 和 `TopBar` 导入 |
| Section / buildListSections / listSortComparator | services/list-sections.ts | 所有列表小部件背后的区块构建器。完整接口面参见 `architecture/services-and-utils.md` 一行 |

`PendingCalendarDropContext` 保持高亮）。自动滚动只在指针位于容器内时才滚动该容器（`useAutoScrollUnderPointer`：否则 dnd-kit 会从另一列滚动被拖动行所在的列表）。`DragOverlay` 显示标签页幽灵，面板拖动时则显示 `PanelGhost`（一张 180px 的卡片：该面板的标签页、三条占位线、一个 `N tabs` 徽标，旋转 −1.2°）—— 通过一个 modifier 相对指针偏移 +12/+10，在指针即将移出窗口之处放置于指针上方 / 左侧 —— 再加上：为拖放区域自身未标注的已接受目标显示一个标签胶囊（"New column"（新建列）、"New band above / below all columns"（在所有列之上 / 之下新建带区）、面板的 "Insert N tabs"（插入 N 个标签页））、一个被提起的日历条目（`calendarEntry` 拖拽数据）或任务行（一个幽灵 `TaskRow`，样式来自 `components/workspace/DragOverlayTask.module.css`）。承载 `TaskDialog`、`CheckinDialog`（放在其后，因此它打开在任务对话框之上）、`TaskEditPopupHost`、`EntityActionHost`、`EditListHost`。挂载时它还会调用 `list-draft-store.restore()`（重新加载之前保留下来的未保存列表编辑）。`UnsavedNavigationGuard`：`useBlocker`（布局处于未保存状态或有列表存在未保存编辑时 pathname 发生变化）→ `UnsavedPrompt`（Save（保存）→ 然后继续；Discard（放弃）→ 然后继续；Cancel（取消）→ | SettingsPage | views/SettingsPage.tsx | 移动版设置（`/settings`，底部标签栏的 Settings（设置）标签页）：以列表呈现 `settings-sections.ts` 中带有被标记为 `mobile` 的部分的那些区块（`MOBILE_SETTINGS_SECTIONS`：Appearance（外观）、People statuses & tags（成员状态与标签）、Database（数据库）、About（关于））；点按某一项会滑入该项 —— 只显示其手机部分（People statuses & tags：只有 Unused people & tags（未使用的成员与标签）一行；Database：Import / Export（导入 / 导出）、File storage（文件存储））—— 并带一个返回箭头；当通过路由状态 `{ section, part? }`（`SettingsRouteState` —— 存储状态 sheet 的 File storage 设置）导航到它时，会打开在那个区块上并滚动到对应部分（`scrollToSettingsPart`）。桌面端在 `SettingsModal` 中显示同样的区块 |

## 弹出层（popover）模式

锚定到点击坐标或触发元素的浮动面板，其定位与关闭都经由共享的 `usePopoverAnchor` 钩子（`hooks/use-popover-anchor.ts`——见 services-and-utils.md）处理。该钩子负责防裁剪翻转（flip-on-clip）+ 钳制（clamp）+ 滚动/调整大小/Escape/点击外部关闭；调用方负责面板及其 `createPortal` 包装。每个弹出层都基于它：`MenuPopover`（连同它一起的还有 `WidgetKindMenu`、`TaskMenu`、布局选择器等；它的子菜单和面板也是如此）、`AnchoredPicker`（行 / 移动端行 / 标签筛选片 / 批量栏选择器）、`RuntimeFilterPicker`、`FollowupPopover`、桌面端 `FilterChipBar` 的各个选择器和筛选（Filters）菜单、`StoragePill`、`CalendarDayPopover`、`EditListPopover`（rect 锚点：其列表的单元格）、`PredicateFieldPicker`、`SwitchToManualPopover`、`StatusEditor`、`TaskNotePopover`、`TooltipBubble`（`bottom-center`）以及 `QuickAddBar` 和笔记的 `@ # /` 弹出框（`NotesNlpPopup`）——两者都是在光标处的 `rect` 锚点。唯一的例外是艾森豪威尔拒绝提示（tooltip），它跟随指针移动，并被约束在其所属小部件内部，而不是整个视口内。

**当需要新增一个弹出层时，只做这件事，且仅做这件事：**

1. 选择锚点：元素锚定的弹出层用 `{kind:'ref', ref}`（面板在滚动时跟随触发元素）；点击坐标弹出层（右键 / contextmenu）用 `{kind:'point', x, y}`。
2. 调用 `usePopoverAnchor({ anchor, open, onClose })`。默认配置会处理滚动关闭 / 调整大小关闭 / Escape / 点击外部关闭。
3. 在 `createPortal(<div ref={panelRef} style={style}>…</div>, document.body)` 内渲染面板 —— 钩子（hook）是唯一应该计算面板位置的地方；使用方不应再另行编写单独的钳位（clamp）/ 翻转（flip）`useEffect`。
4. 对于位于面板之外的嵌套飞出层（flyout）（例如 `MenuPopover` 的子菜单和面板），传入 `extraInsideRefs: [flyoutRef]`，这样外部点击（outside-click）会忽略它们。
5. 那些应在滚动时*重新定位*而非关闭的引用锚点（ref-anchored）弹出层（`RuntimeFilterPicker`）传入 `closeOnScroll: false, closeOnResize: false` —— 对 `kind: 'ref'` 锚点，钩子的重新定位模式会生效，而 `kind: 'point'` 锚点保持静止。
6. 自带特殊 Escape 逻辑的弹出层（例如 `MenuPopover` 的“先关闭子菜单，再关闭菜单”）传入 `closeOnEscape: false` 并保留自己的键盘处理器。`consumeEscape: true` 会在那里拦截用于关闭弹出层的 Escape（任务对话框中的行选择器（row picker）不会连带关闭该对话框）。
7. 打开期间尺寸会变化的面板（选择器（picker）的列表随输入而收窄、编辑器（editor）逐渐变大）传入 `observeSize: true`；锚点并非触发器时（整行）传入 `anchorIsInside: false`，这样点击它就会关闭弹出层。
8. 在弹出层之上打开的层无需任何处理：堆叠在其上方的层中的一次按键或 Esc —— 即 `<body>` 中更靠后的 portal 根节点（`utils/dom-layers.isInLayerAbove`）：在其处于打开状态期间打开的菜单、对话框或确认框（confirm）—— 并不属于其外部；而当其上方有模态框（modal）打开时，在无焦点状态下按下的 Esc 属于那个模态框（`hasModalAbove`）。因此，选择器会在它所打开的成员 / 标签菜单、编辑器或确认框之后保持打开，并且每次 Esc 只关闭一层（`e2e/picker-entity-menu.spec.ts`）。

**禁止事项：**

- 不要针对 `getBoundingClientRect()` 计算、滚动监听器（scroll listener）、尺寸变化监听器（resize listener）或文档级（document-level）的 `mousedown` / `keydown` 外部点击处理器，为每个组件单独编写 `useEffect`。这些内容全部已被并入该钩子。
- 不要从*调用点（call site）*对弹出层做 portal 化（在使用方处写 `createPortal(<MyPopover/>, body)`）。上述弹出层都是在*内部*进行 portal 化的 —— 在调用点添加一个包装用的 portal 会无害地形成双重 portal，但会掩盖意图。

## DnD 诊断开关（`?debug-dnd=1`）

在 URL 后面附加 `?debug-dnd=1`，即可记录任务拖放路径（列表小部件、艾森豪威尔和仪表盘中的行，以及拖放到日历日期和象限上的日历条目）的每一个守卫分支和解析路径。当某次拖放无声地落空（控制台没有报错、也没有可见反馈）时，打开这个开关并重新执行一次拖放，控制台就会输出整条判定链——选定的碰撞规则 → 解析得到的 `over.id` → 各守卫的结果 → 最终的分发。

该开关在模块加载时通过 `utils/debug-flags.ts` 读取一次；每个调用点都使用带门控的 `dndLog(label, payload?)` 辅助函数，因此在开关未开启时生产环境的控制台保持安静。这是**永久性的诊断基础设施**——少量的打包体积开销（几十个空操作字符串字面量）换来的是实打实的诊断价值。

**包装点：**
- `utils/task-dnd/dispatch.ts` —— `dispatchTaskDrop` 的每一个分支（无活动任务、日历日期改期、日历日期选择被取消、艾森豪威尔投放及其结果、未处理的情况）。
- `utils/task-dnd/collision.ts` —— `buildTaskCollision` 的规则选择（无活动兜底、命中规则并附带索引 + 算法 + 可放置目标数量、无规则命中兜底）。

工作区标签页的拖动和列表行的重排不经过这些路径（它们是对测量出的几何信息做命中测试），因此不会被记录。
